# 小说创作工作区架构与工作流

小说工作区是通用 AI 平台的独立业务模块。AI 提供大纲、场景计划、正文草稿、审校建议和记忆候选；作者负责确认设定、采纳正文及批准记忆。数据库保存正式资料，浏览器仅暂存尚未保存的草稿恢复副本。

## 模块边界

- 前端入口：`/literature`，作品入口：`/literature/books/:bookId/overview`。
- 子页面：`framework/:kind/:entryId`、`drafts/:chapterId`、`chapters/:chapterId`、`confirm/:jobId`、`settings`、`memory`、`tasks`，支持地址直接访问和浏览器前进后退。旧 `canon/:kind` 地址继续兼容。
- 后端 API：`/api/literature`。不使用营销对话的系统提示词或产品知识检索规则。
- 复用平台的 LLM 配置和当前 API Key 方案，但密钥只在服务器读取，不出现在作品导出及上下文包中。
- 单作品单个运行任务。独立模块不更改图片、视频、音乐和旧有对话流程。

## 数据模型

| 数据 | 职责 |
| --- | --- |
| users / sessions | 作者账号、管理员角色、加盐密码派生值、服务端会话 |
| books | 作品简介、题材、文风、全书约束、模型配置、全局版本 |
| entries | 大纲、分卷、主支线、人物、剧情、物品、场景、势力、世界、文风、伏笔；parent_id 保存真实父子层级 |
| chapters | 章节序号、目标、场景推进、禁止事项、关联实体、正文、当前版本及确认版本 |
| versions | 每次保存的正文及章节计划快照，恢复时创建新版本，不删除旧版本 |
| facts | 已确认正文提取的状态、事件、认知和伏笔，关联来源章节及版本和原文依据 |
| jobs | 任务状态、执行阶段、输入、上下文快照、结果、失败原因及版本绑定 |
| audits | 设定修改、正文保存、采纳及删除等操作的审计记录 |
| literature_imports / import_chapters | 解码后的完整原稿、批次、请求幂等键、分章预览、原文范围与完整/未完状态 |
| chapter_sources / import_units | 作者导入来源、绑定正文版本的分段、持久化分析状态、审核结果及重试次数 |
| import_evidence / takeovers | 框架及事实的引文和字符位置、公开与时序边界、接管检查快照及续写目标 |

`entries.status` 区分 `candidate` 与 `confirmed`。候选资料不进入写作上下文。主支线和大纲是未来计划，不等同于发生过的事实。`reveal_chapter` 控制整个条目何时可供 AI 使用；不应把后期秘密混入早期公开的人物条目，应拆成独立的延迟开放条目。

创作框架按剧情、人物与世界、创作规范组织为可折叠树。节点在主区域直接填写，可指定同类上级节点；服务端拒绝循环和跨作品父节点。子节点继承父节点的确认状态及披露时间限制，引用子节点时上下文也包含其上级约束。删除父节点不会删除子节点，直接子节点移到分类根。

创作计划、空稿、AI 待采纳稿与正式正文分开。已确认的 AI 正文，以及作者明确确认导入的完整旧作章节，均可进入正式目录；二者保存不同来源，不伪造 AI 写作记录。未完成导入片段仍是草稿。正式正文标题、阅读页与 TXT 导出使用确认版本，阅读页只读，修订需进入创作计划，未确认的新修订不会替换正式内容。作品配置、框架节点和记忆确认均在主区域编辑；只读上下文及版本检查仍可使用对话框。

### 操作界面

- 作品内采用作品导航、主编辑区、AI 助手三栏；平台总菜单收成窄栏，可展开完整菜单。作品目录与助手均可收起，专注模式退出后恢复原布局。
- 作品导航通过“创作框架 / 正式正文”切换，框架保留真实父子树与创作计划，并支持搜索；正文只显示符合正式来源与确认条件的章节。
- 框架节点分为基本信息、核心要点、约束与状态，在主区域填写；保存操作固定在编辑区底部，不使用弹窗填写。
- AI 助手按页面显示操作。章节区提供规划、写作、审校、记忆阶段；改写与大纲保留在更多操作中。非章节页不再显示不可用的章节操作。
- 正式阅读默认收起助手，控制阅读行宽，支持字号与章节翻页。阅读字号保存在本机；正式文本仍然只读。
- 窄屏用“目录 / 编辑或阅读 / AI 助手”切换，不把多个面板纵向堆叠。面板切换不改变路由、草稿或正在运行的任务。

锁定条目需要明确解除锁定才能修改。所有写入都验证所属作品和作者，不接受客户端传来的作者 ID 作为权限依据。

## 作者工作流

1. 创建作品，定义题材、简介、文风和全书约束。
2. 手动或由 AI 构思大纲。AI 大纲先保存为候选，作者编辑并改成已确认状态。
3. 建立人物、世界、物品、主支线和伏笔。关键规则可以锁定。
4. 在框架树中新建创作计划，填写目标、推进顺序、不可发生事项、叙事视角和关联实体。此时不会进入正式正文目录。
5. AI 先组织场景方案，再写单章草稿。生成结果保留在任务中，不覆盖正文。
6. 作者采纳到草稿，修改正文。编辑器自动保存并保存版本。
7. 运行一致性审校，依据定位到的原文人工决定修订。审校不自动改稿。
8. 为最终草稿提取记忆，检查事实、原文依据、知情人物和摘要。
9. 在主区域确认正文与所选记忆。在同一数据库事务中更新确认版本、记忆与审计；有 AI 写作来源的确认正文进入正式正文目录。
10. 下一章上下文使用已经确认且未失效的历史事实。未采纳任务、未确认正文和未来事实不得进入正式历史。

## 旧作导入与接管

入口为 `/literature/books/:bookId/imports`，支持批次列表、`imports/new` 上传、`imports/:importId` 预览和进度、`imports/:importId/units/:unitId` 页面内审核。无需弹窗填写。

```text
TXT / Markdown -> 分章预览 -> 作者确认原文 -> 持久化分段分析
  -> 逐段或安全范围内批量审核 -> 接管完整性检查 -> 末尾续写
  -> 原有审校与记忆确认 -> 下一章
```

- 单批上限 200 万字符，浏览器文件上限 8 MB；超过上限按卷追加。支持 UTF-8 和 GB18030/GBK 解码，不支持 Word、PDF 或 OCR。原稿完整保存在 SQLite，可下载解码后的原始文本，也包含在 JSON 导出中。
- 识别常见中文/英文章节与卷名，无标题时按段落分段。分章预览允许改标题、排序、排除和标记末尾未完片段。正文不在预览中改写。超过 10 万字符的单章拆为片段，以适配原有章节存储边界。
- 去重使用内容校验值与章节身份，而不是仅凭重复句子。同一批不同章节中的合法重复文字不会被丢弃。同名异文阻止导入，要求改名或排除；不会覆盖旧稿。上传请求幂等，原稿确认不调用模型。
- 分析长度可选 3000/6000/10000 字符，段落边界优先；各段保留连续字符范围。单作品分析与普通 AI 创作任务互斥。模型只接收当前有界原文分段，逐段抽取摘要、实体、回溯大纲、主支线、物品、事件、秘密与文风。
- 状态为 pending/running/ready/accepted/failed/stale，父任务可暂停与继续。失败停止队列，不自动重复付费调用；继续只重试失败和未完成段。服务重启改为暂停，已完成段保留；正在请求中的那一段可能需要重新调用，不能承诺上游计费恰好一次。
- 失败或过长的分段可以继续细分。旧段标记 superseded 留档，新段覆盖原有字符范围，不删除原始出处；完成度和接管检查只计算当前版本的有效分段。
- AI 结果先进入导入审核区，不直接成为正式设定。引文必须逐字存在于分段中；作者可以修订候选内容、排除条目、明确实体复用和别名对应。复用不覆盖已有档案或锁定规则。回溯剧情按批次组织成框架树，与未来剧情候选区分。
- 所选资料必须明确公开程度与事件时序。限定知情需指定人物；不确定结论拒绝确认。回忆中的状态转为历史事件，不能覆盖当前状态；同章按原文位置而不是审核先后决定最近状态。批量确认最多 20 段，仅允许无问题清单、公开且时序明确的结果，且要求作者显式核对。
- 引文、版本、原文字符位置和审核修订持久化；新建的框架条目可跳回分析页查看原文。实体别名只是候选，不自动合并不同人物。
- 接管检查要求所有已导入完整章节的当前正式版本有连续、全部已审核的分析覆盖，且没有未确认修订。检查通过才建立接管快照和续写计划。本版仅接管作品末尾，不支持在中间章节自动创建分支作品。
- 未完片段在接管时建立新计划版本，保留原始版本。续写任务明确只生成后续内容，并在候选稿中接在原文后；完整未完片段超出上下文预算时拒绝，不静默截断。仍需作者采纳、审校和确认记忆才成为正式章节。
- 前文或重要设定变更会让相关事实、分析和接管快照失效。作者明确确认当前保存稿后重建分析；旧原稿、旧版本、旧出处不删除。追加上传的新批次需要完成同样的审核与接管检查。

百万字测试覆盖无损分段与实际入库，不代表对真实百万字小说的语义提取准确率做出保证。当前为逐段提取、作者审核和结构化检索，不是全书一次性推理或训练模型；全书高层摘要和复杂非线性时间推演仍需要作者整理与后续扩展。

## 长篇上下文

`context.js` 负责把业务数据组装成可导出的上下文包，不依赖模型聊天会话的长期记忆。

上下文包包含作品基准、当前章节计划、系统约束、必需设定、计划线索、历史状态、历史事件、近期摘要、当前草稿和纳入清单。

- 时间边界：只读取目标章节之前的正式事实，不读取未来章节的事实。
- 状态边界：同一实体同一状态只保留此前最近的确认值；事件作为追加记录，不因同名事件被覆盖。
- 认知边界：保留 `known_by` 人物 ID；指定视角人物时，写作上下文排除其尚不知情的私密事实。审校上下文保留知情边界供检查使用。摘要和设定正文仍需作者检查是否夹带秘密，不能仅依赖结构化字段。
- 必需资料：锁定设定、世界规则、文风以及本章关联实体优先纳入；关联实体的当前状态不允许静默丢弃。
- 检索：当前实现为关联实体加关键词匹配、时间排序，不是向量检索。检索来源是作品数据库，不与公司产品知识库混用。
- 预算：默认 26000 个序列化字符，清单列出省略数量。这是上下文体积控制，不是精确的模型 token 计算。
- 审校、改写和记忆提取必须包含完整当前正文；超过预算则拒绝任务并要求按场景拆分，不能截断后伪装成完整审校。
- 普通写作上下文可保留当前草稿末段，记录省略的前缀字数；作者可查看及导出实际发给模型的上下文包。

更大的全书规模不会要求每次发送完整正文。数据库保留原始正文和版本，正文事实有明确来源，摘要属于可重新生成的辅助资料。

## 修订与失效

每个任务绑定 `book_revision` 和 `chapter_revision`。任务完成时如果资料已经改变，结果标为 `stale`；采纳接口也再次验证版本，旧结果不能覆盖新稿。

修改前文会使本章及后续记忆失效，并把后续章节标为待复核。重新确认后续章节是显式操作，不在后台偷偷改写。世界规则或文风等重要设定修改也会触发复核。仅更换模型或作品标题不会废弃已确认剧情记忆。

当前失效策略偏保守：已有设定修改可能影响全部章节。后续可增加实体及事件依赖索引，把范围缩小到确实受影响的章节。保守策略成本更高，但不会默默保留可能不正确的旧记忆。

## 任务执行

支持 `outline`、`plan`、`write`、`rewrite`、`review`、`memory`。

状态为 `queued`、`running`、`ready`、`applied`、`failed`、`cancelled`、`stale`。前端按真实阶段轮询，不显示伪进度。任务创建带请求 ID 防止重复提交；数据库事务领取任务，避免同一任务重复调用模型。

取消会中断 LLM 网络请求；迟到结果不会再写入可采纳状态。服务重启后未完成任务标记失败，原稿保留，作者重新发起，不自动重复付费调用。

当前使用单机进程内执行器与 SQLite 持久化任务。正式部署使用单个后端进程；尚不支持多工作进程共享调度或分布式队列。后续扩展可沿同一任务契约替换为独立 worker 和 PostgreSQL。

## 登录与部署

文学创作有独立的真实账户和服务端会话，不把旧平台的浏览器用户偏好 ID 当作登录身份。首位作者初始化为管理员，之后的作者由管理员创建；普通作者仅能访问自己作品。当前没有团队共享或跨企业租户管理，不宣称整个平台已完成统一登录。

- 密码使用随机盐及 scrypt 派生，最短 10 字符。
- 会话令牌随机生成，数据库仅保存令牌摘要；Cookie 为 HttpOnly、SameSite Strict。
- 写入需专用请求头，并校验浏览器 Origin；登录有独立限流。
- 生产环境首次初始化必须配置 `LITERATURE_SETUP_KEY`，不能在公网开放无口令初始化。
- HTTPS 部署设置 `LITERATURE_SECURE_COOKIE=true`。
- 反向代理或分离部署时设置准确的 `LITERATURE_ALLOWED_ORIGINS`，多个来源用逗号分隔。
- 数据库路径通过 `LITERATURE_DB_PATH` 指定；默认 `server/cache/literature.sqlite`。数据库和密钥不提交到 Git。
- 备份应包含 SQLite 数据库和 WAL 一致性快照。可以停写后备份，或使用 SQLite backup API；不能仅复制一个正在写入的主库文件。

局部登录不保护旧有管理 API。企业对外部署前，仍需完成全平台统一认证、管理员配置权限、密钥加密和模型使用授权，不能仅因为小说模块有登录就直接公网发布整个旧平台。


自动化覆盖章节时间边界、候选排除、最近状态、预算超限、来源校验、账户隔离、草稿采纳、记忆确认、版本冲突、任务失效、取消和幂等。浏览器验证覆盖完整创作流程、地址恢复、深浅主题及多种视口；测试使用模拟模型，不消耗真实 API 额度。

## 后续扩展

已经预留结构化实体资料、出处和上下文包契约，可继续加入分卷摘要、语义检索、实体关系图、依赖精确失效、团队编辑审核、不同流程阶段的模型策略，以及小说到剧本、分镜和视频的交付链。

AI 能遵守约束的程度仍受模型能力和资料质量影响。来源匹配只能验证引用存在，不能证明推断正确；审校结果不是质量保证。人工确认、版本回溯和明确的未确认状态是不可省略的控制点。

当前事实的有效时间按章节顺序处理，故事时间字段提供叙事标注，尚不是支持复杂倒叙的时间模拟器。大规模非线性叙事需要后续增加独立事件时间和状态时间区间；不能把章节序号自动当成现实日历。
